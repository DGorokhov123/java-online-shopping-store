# Online Shopping Store

Backend Интернет-магазина. Приложение обеспечивает полный цикл продажи товара - от онлайн-витрины до подтверждения доставки.

В приложении используется микросервисная архитектура, построенная по принципам DDD. Выделены следующие bounded contexts:
- **Витрина** (модуль shopping-store) - онлайн-каталог продукции с ценами и краткой информацией о наличии товара
- **Склад** (модуль warehouse) - перечень товарова на складах с возможностью бронирования под конкретный заказ 
- **Корзина** (модуль shopping-cart) - собираемая покупателем корзина товаров для заказа
- **Заказы** (модуль order) - оформленный заказ со сложным жизненным циклом, включающим сборку, оплату, доставку, подтверждение.
- **Платежи** (модуль payment) - обработка платежных данных и взаимодействие с гипотетическим платежным шлюзом банка
- **Доставка** (модуль delivery) - сервис службы доставки

Взаимодействие микросервисов между собой осуществляется с помощью REST-контроллеров и Feign-клиентов, 
имплементирующих общие API-интерфейсы, что обеспечивает гарантию совместимости API. 
Приложение использует Spring Eureka Discovery для управления инстансами микросервисов, 
а также Spring Cloud Gateway для доступа к системе извне. 
Эти технологии обеспечивают балансировку нагрузки между микросервисами как для внешних вызовов (через Gateway), 
так и для внутренних (через Feign-клиенты).

## Гарантированная доставка сообщений при помощи Polling-based Outbox Pattern

Во взаимодействии сервисов между собой применен подход, обеспечивающий 
гарантированную доставку с помощью REST-запросов.

За основу взят шаблон Transactional outbox
https://microservices.io/patterns/data/transactional-outbox.html 
и творчески доработан:

- вместо scheduling используется Polling publisher. Pollers запускаются в отдельных потоках и 
опрашивают в цикле базу данных, обрабатывая новые данные
- используется флаг модифицикации данных для уменьшения нагрузки на БД
- вместо таблицы Outbox используется маршрутизация сущностей на основе статусов
- Poller запрашивает сущность в определенном статусе, делает вызовы REST и меняет статус,
переводя сущность на следующий шаг обработки
- Пока REST не вернет нужный результат, статус не изменится и Poller будет повторять попытки
- По таймауту поллер завершит попытки и переведет сущность в failed-статус для ручной обработки
- Poller реализован как абстрактный класс и переиспользуется в коде

# Инфраструктурные модули (папка /infra)

Используются:
- Spring Boot
- Spring Cloud Eureka server
- Spring Cloud Config server
- Spring Cloud Gateway server

## Discovery Service
Модуль **discovery-server** реализует Service Registry - центральный управляющий модуль, 
обеспечивающий взаимодействие между микросервисами, load balancing, multi-instance, health-checks и т.д.

## Configuration Service
Модуль **config-server** реализует паттерн External Configuration в качестве центрального хранилища конфигураций 
для всех микросервисов, кроме discovery-server.

## Gateway Service
Модуль **gateway-server** реализует паттерн API Gateway. Он работает как единая точка входа извне для всех микросервисов.

# Модули основного приложения (папка `/commerce`)

Приложение состоит из 6 интегрированных микросервисов. Каждый микросервис работает с отдельной базой данных
(для упрощения в данном релизе реализованы как разные схемы в единой бд).
Взаимодействие осуществляется посредством Feign-клиентов с поддержкой circuit breaker на базе Resilience4j.
Также для авторизации используется Spring Security.

Используется кеширование на базе Caffeine (модуль shopping-store) и ConcurrentHashMap (модуль shopping-cart).
Также используется логирование на базе AOP (модули shopping-store, shopping-cart, warehouse).

Используются:
- Java ٩(◕‿◕｡)۶
- Spring Boot
- Spring MVC (REST)
- Spring Data JPA (Hibernate)
- Spring Cloud Discovery and Configuration
- OpenFeign client + Resilience4j
- PostgreSQL
- Spring Security
- Caffeine

## Модуль общей библиотеки

Модуль **interaction-api** содержит общие классы и интерфейсы, используемые в разных модулях, в частности:
- Интерфейсы описания API
- Вспомогательные классы Feign-клиентов
- DTO
- Исключения и обработчики исключений
- Кастомные валидаторы и аннотации.
- Аннотации логирования
- Абстрактный poller для реализации Polling-based Outbox Pattern 

## Сервис "Витрина" `shopping-store`

Микросервис **shopping-store** - online-витрина магазина. Основная сущность: **Product** (товар в продаже). 

Поддерживает следующие операции:
- Добавить новый товар
- Обновить существующий товар
- Удалить товар
- Обновить информацию о наличии товара
- Получить карточку товара
- Получить цены по списку товаров
- Получить список товаров с пагинацией

## Сервис "Склад" `warehouse`
Микросервис **warehouse** - операции со складом. 
Основные сущности: **WarehouseProduct** (товар на складе), **Booking** (бронирование товара)

Поддерживает следующие операции:
- Добавить товар на склад
- Проверить количество товара
- Изменить количество товара
- Получить адрес склада
- Передать товар в доставку
- Принять возврат товаров на склад
- Забронировать и собрать товар
- Откатить бронирование
- Списать товары после доставки

## Сервис "Корзина" `shopping-cart`
Микросервис **shopping-cart** - покупательская корзина. Основная сущность: **ShoppingCart** (корзина с товаром)

Поддерживает следующие операции:
- Добавить товар в корзину
- Удалить товар из корзины
- Изменить количество товара
- Отменить текущую корзину
- Получить актуальную корзину

## Сервис "Заказы" `order`
Микросервис **order** - управление прохождением заказа от оформления до доставки и подтверждения. 
Основная сущность: **Order** (оформленный заказ)

Поддерживает следующие операции:
- Расчитать стоимость заказа
- Расчитать стоимость доставки
- Получить все заказы пользователя
- Создать новый заказ из корзины
- Вернуть товар при отмене заказа
- Обработать сообщение об успешной оплате
- Обработать сообщение об отмене оплаты
- Обработать сообщение о начале доставки
- Обработать сообщение об успешной доставке
- Обработать сообщение об отмене доставки
- Обработать сообщение об успешном бронировании
- Обработать сообщение об отмене бронирования
- Обработать сообщение о подтверждении успешного завершения заказа

## Сервис "Платежи" `payment`
Микросервис **payment** - приложение для управления платежами. Основная сущность: **Payment** (Платеж)

Поддерживает следующие операции:
- Создать оплату для заказа
- Рассчитать стоимость товара в заказе
- Рассчитать полную стоимость заказа
- Сообщить об успешной оплате
- Сообщить об отмене платежа

## Сервис "Доставка" `delivery`
Микросервис **delivery** - приложение для управления доставкой. Основная сущность: **Delivery** (Доставка товара)

Поддерживает следующие операции:
- Создать доставку для заказа
- Запустить процесс доставки
- Сообщить о получении товара в доставку
- Сообщить об успешной доставке
- Сообщить об отмене доставки
- Рассчитать полную стоимость доставки
